# 학습앱 파이프라인 규약 (정본)

> 출처: Study Vault 구현 기획서 §3 (2026-09-02). 모든 학습앱은 이 4단계 범용 파이프라인을 따른다.
> 각 단계의 **구체 수단은 프로젝트가 선택한다** — 수단을 규약으로 강제하지 않는다.

```
[1 EXTRACT 근거 수집·추출] → [2 VERIFY 검증] → [3 GENERATE 생성] → [4 OUTPUT 결과물]
```

## 단계 정의

1. **EXTRACT** — 학습 콘텐츠의 근거가 될 원천 데이터를 수집·추출한다.
   (예: 논문 PDF 전문 텍스트 추출, 공식 매뉴얼/문서, 교과서 개념 정리, 문제은행, 크롤링한 서지 메타데이터, 실습 로그)
2. **VERIFY** — 콘텐츠에 실릴 모든 사실·수치를 근거와 대조하고 **근거 등급을 태깅**한다.
   등급 체계(전 앱 공통): `원문 대조` / `공식 문서·초록 기반` / `교과서 상식` / `추정(명시)`.
   **근거 없는 수치는 싣지 않는다.**
3. **GENERATE** — 검증된 콘텐츠를 결과물로 만드는 임의의 생성기.
   파이썬 빌더여도, 수작업 저작이어도, LLM 보조 작성이어도 된다.
4. **OUTPUT** — 결과물. 단일 HTML을 권장(오프라인·이식성·아티팩트 호환)하되 강제하지 않는다.
   단, Vault 편입 필수 조건 2가지: ① `apps.json` 매니페스트 등록 ② 공용 진도 모듈(`shared/progress.js`) 연동.

## 프로젝트 유형별 매핑 예시

| 유형 | EXTRACT | VERIFY | GENERATE | OUTPUT |
|---|---|---|---|---|
| 논문기반 (MIL 온보딩) | PDF 전문 추출, Crossref/OpenAlex 메타, 홈페이지 크롤링 | 수치를 추출 텍스트와 대조, 등급 배지 | content .py + build 스크립트 | 단일 HTML SPA |
| 개념기반 (최적설계 총정리) | 교재·매뉴얼·실습 정리 | 교과서 상식 수준 검수 | 수작업/LLM 보조 저작 | 단일 HTML 문서 |
| 문풀기반 (과목앱) | 강의자료·기출 유형 분석(원문 미포함) | **검산 게이트** — 수치·기호를 독립 재계산과 대조, 통과분만 탑재 | 문제은행(구조화 데이터) → 퀴즈 엔진 빌드 | 퀴즈 웹앱 |
| 전공 강의기반 | 강의노트·필기 | 원 노트 대조 | 자유 | 자유 |

## 기록 의무

각 앱 폴더의 `README.md`에 **"이 앱은 각 단계를 무엇으로 수행했나 + 근거 원천이 어디 있나"** 를 남긴다.

## 앱 추가 절차 (확장성의 전부)

1. `apps/<id>/` 폴더에 결과물 넣기 (`id`는 kebab-case — **localStorage 키·폴더명에 쓰이므로 불변**)
2. `README.md`에 파이프라인 기록
3. `shared/progress.js` 연동 (`data-rid`/`data-read` + `Vault` API)
4. `apps.json`에 항목 1개 추가
5. push — 허브 코드는 건드리지 않는다.
